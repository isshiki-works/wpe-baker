The hard part

Different rhythms. One seamless loop.

A wave repeats every 7.3 s, a sway every 11.1 s, a particle cycle every 4.6 s and a video every 20 s. They may take too long to return to their starting states together for a practical video loop. Periodica solves each component’s period, then adjusts its playback speed within the selected budget so animations that need to play together form a seamless loop.

BUDGET

Control how much the animation changes

The three precision presets set a visible-change budget: Efficiency allows up to 5%, Balanced up to 3%, and Quality finds the smallest change that still closes the loop. The program favors smaller adjustments and reports the periods and speed changes it actually uses.

GUARDS

Keep retiming visually subtle

Each component has its own adjustment limit. For very slow motion, the program also considers displacement and changes in speed when checking whether a loop can close. Content that cannot meet the conditions stays live, with the layer and reason listed in the report.

PROOF

Verify loop seams against the original scene

During generation, the program renders extra frames around the loop point, checks the encoded seam and compares the assembled result of baked content and live layers. Outputs are accepted once the corresponding checks pass.

Refresh rate

High refresh rates. Lower power use.

As playback frame rate rises, the original scene has to render more images in real time. Baking periodic animation into video lets the video decoder handle that part of playback, reducing repeated work on the 3D engine. Retained clocks, audio response and other live content continue to run as before.

Under the hood

From period analysis to offline rendering.

A Wallpaper Engine scene can contain hundreds of shader variants, particle systems, script controllers and video layers. Finding two similar frames is not enough to bake them into a loop: the program needs to know how animation changes over time, and which parts must keep responding to live input.

Periodica replaces the early library of period equations with shader time analysis. It applies abstract interpretation to the compiled SPIR-V, following time through the data flow to derive cycles, continuous drift and animation that settles after a while. New effects no longer need a hand-written equation of their own; unfamiliar custom shaders can be analyzed too.

Once the periods are known, the program looks for parameters it can adjust locally. Waves, glows and scrolling within one effect no longer have to speed up together. Motions that can be adjusted independently are coordinated separately, and independent video groups repeat at their own intervals.

Author scripts are also included in time analysis. Constants, periodic changes and opening animations can be identified; where state carried between frames can be simulated exactly, the program searches for that state to recur. Content that depends on the mouse, audio or the clock stays live.

To put the baked result back into the original scene, Periodica also handles transparency, blending order and HDR intermediate images. Brightness outside ordinary video range is mapped into the video and restored by a generated shader, so cached content can continue through the author’s existing effect chain.

Offline rendering

Redesigning the rendering pipeline for offline generation

Building on open-wallpaper-engine, Periodica reworks scene execution and the Vulkan offline rendering pipeline. Shaders, scripts, particles and video advance in deterministic time steps, with simulation, drawing and sampling scheduled separately. Warm-up no longer reads back images that will be discarded, loop-start searches draw only the frames needed for comparison, and independent video groups are generated at their own periods.

In early versions, transparent frames passed through full-frame readback, CPU scanning, lossless intermediate video and a second encoding pass. Cropping, transparency processing and loop crossfades now run in the GPU pipeline, which feeds the result directly to the hardware encoder. Fewer data transfers, intermediate files and repeated computations make the entire generation process faster.

In a same-scene comparison on an RTX 5090 D v2, full 4K baking time fell from 108 seconds to 17 seconds, more than a 6-fold speedup. A separate long-scene 4K test reached 3.7 times real-time speed from analysis through generation, producing 4 minutes 18 seconds of 4K 60 FPS animation in about 70 seconds.

Real-world validation

Refined through testing.

We refined compatibility and generation performance through regression testing on 489 real Workshop wallpapers and 4K rendering and video export tests across 12 scenes of different types.

On the same set, scenes eligible for baking increased from 244 in version 1.0.2 to 444, reaching 90.8% coverage. Coverage among the 41 popular wallpapers in the test set rose from 22 to 37.

2.1 continues to optimize the shared rendering path. Across the same 24 test scenes, median full-frame rendering throughput rose 2.00× on an RTX 5090 D v2 and 1.58× on an Intel Arc B390 relative to 2.0.0.

Results from five open-source renderers serve as performance references. In the 4K scene tests on an RTX 5090 D v2, Periodica averages 2.72–6.28× the reference rendering speeds, with video export averaging 2.79× real time.

1.x · Released

Wallpaper Engine, Windows

Bake repeating scene animation into video and place it back alongside retained live content. Wallpaper Engine is Periodica’s first application area.

2.0

Performance update

Replace individually maintained period equations with shader and script time analysis, expanding the range of animation that can be baked. Give independent video groups their own loops, improve HDR intermediate-image handling, and reduce readbacks, repeated encoding and waits during generation.

2.1

Rendering efficiency

Reduce repeated preparation, state binding and snapshot copies, and reuse unchanged render results across frames, significantly raising offline rendering throughput with identical images.

2.x

The general-purpose era

Use caching, reuse, precomputation and deterministic replay to bring more real-time layers within practical baking range, including a new AI-accelerated generation pipeline.

3.0

Temporal reconstruction

Use history and motion information to reconstruct frames, reducing the work of rendering each frame from scratch, and explore cooperation between the GPU and NPU.

FAQ

Short answers.

What is the main benefit?

Run your favorite animated wallpaper with lower power use.

Which wallpapers benefit most?

Scenes with demanding, repeating animation have the most to gain. The examples above used 18–97% less iGPU power after baking. Lightweight scenes have less work to save; scenes with extensive interaction keep their live content alongside the baked animation.

Does the loop look different from the original?

Choose Efficiency, Balanced or Quality to set the visible-change budget. The report lists every retimed component and its exact adjustment percentage. Each seam is checked against the original scene's motion before the output is accepted.

What do I need?

Windows, Wallpaper Engine, and a GPU for the offline render. The portable build has no installer and no Python. Baking a typical scene takes minutes; the video decoder handles baked content while retained live layers continue rendering.

Is it open source?

Yes. Tooling under MIT, the renderer under GPL v2; full source, third-party notices and build records are in the repository.
