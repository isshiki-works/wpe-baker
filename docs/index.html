The hard part

Different periods. Periodica brings them into one loop.

A wave repeats every 7.3 s, a sway every 11.1 s, a particle cycle every 4.6 s and a video every 20 s. They may take too long to return to their starting states together for a practical video loop. Periodica solves each component's period, then adjusts its playback speed within the selected budget so the animations share one common loop.

BUDGET

Control how much the animation changes

The three precision presets set a visible-change budget for each component: Efficiency allows up to 5%, Balanced up to 3%, and Quality finds the smallest change that still closes the loop. Yuri's 100 periodic components were reconciled into one 180.4 s loop; Nijika's 20 into 44 s; Ayanami Rei's scene closes in 56.2 s with a total retime of 4.68%.

GUARDS

Keep retiming visually subtle

The slowest visible component completes at least three cycles per loop; visible drift stays under 0.2 px/s; sways are retuned in frequency only, never in path. Every retune is bounded per component and listed in the report. If the rules cannot be met, the layer stays live and the report says which one.

PROOF

Every seam verified frame by frame against the original

Every output is rendered past its loop point and compared tile by tile with the original's next frame before it is accepted; that proves the loop closes, and the per-component budget bounds how far any motion drifts from the original over the whole loop.

The tool

Drop a scene in, get a verdict.

Two settings, one analysis result. Animation precision limits how much the animation can be retimed; Interaction controls how mouse and audio effects are handled. More settings are available under Advanced.

From steamapps\workshop\content\431960. The output directory is Wallpaper Engine's own project folder, so the result appears in its list.

02

Animation precision · Interaction

Quality, Balanced and Efficiency set different visible-change budgets; Balanced is the default. If the current precision setting cannot produce a closed loop, the analysis tries the next precision preset and reports the one it selects. Interaction offers Keep, Fixed view and Off for mouse and audio effects. Clocks, dates and media text stay live in every mode.

03

Read the verdict

The result is one of four states. "Not included in this bake" lists the content excluded from baking. If the current settings cannot close the loop but another combination can, the report offers a suggestion you can apply with one click.

Refresh rate

High refresh rates. Lower power use.

Higher playback frame rates require the original scene to render more frames in real time. Once fully baked, the video decoder handles most of the work, reducing the 3D engine's real-time rendering load. This project started on a laptop with an integrated GPU.

  • Animation tracks, sprite sheets, particle cycles
  • Embedded video loops and their timebases
  • Static art, at full resolution

  • Mouse parallax and pointer effects

Under the hood

From period analysis to offline rendering.

Wallpaper Engine's scene format is undocumented. Rendering it frame-exact offline means handling hundreds of shader variants, particle systems, script controllers and video layers.

Periodica combines a multithreaded Vulkan offline renderer for Wallpaper Engine scenes, an analytic period solver, a layer allocator, an encoding pipeline with hardware decoding checks and a power measurement system. Performance tuning cut the bake time for a 25,599-frame scene from 2,566 s to 214 s. The full library of 78 scenes can be baked in one afternoon, with one bake running at a time.

Wallpaper Engine, Windows

Bake repeating scene animation into video and place it back alongside retained live content. Wallpaper Engine is Periodica's first application area.

1.1

Performance update

Reduce readbacks, repeated encoding and unnecessary waits to make faster-than-realtime baking faster still. Optional output-matched effect resolution further reduces work beyond the actual output size.

1.2

General baking acceleration

Use caching, reuse, precomputation and deterministic replay to bring more real-time layers within practical baking range. Neural networks are considered only where they deliver a measured benefit.

1.5 · Beta → 2.0 · Stable

Temporal reconstruction

Use history and motion information to reconstruct frames, reducing the work of rendering each frame from scratch. Validate the approach in beta, then deliver it as a stable capability in 2.0 while exploring cooperation between the GPU and NPU.

FAQ

Short answers.

What is the main benefit?

Run your favorite animated wallpaper with lower power use.

Will it reduce resource use for every wallpaper?

Lightweight scenes offer little room for savings, and the tool tells you before rendering. Heavy scenes dominated by periodic animation are where the 46–96% reductions come from. For scenes with extensive interaction, the deterministic core is baked while interactive and live content is handled separately.

Does the loop look different from the original?

Choose Efficiency, Balanced or Quality to set the visible-change budget. The report lists every retimed component and its exact adjustment percentage. Each seam is checked against the original scene's motion before the output is accepted.

What do I need?

Windows, Wallpaper Engine, and a GPU for the offline render. The portable build has no installer and no Python. Baking a typical scene takes minutes; playback needs only hardware video decode.

Is it open source?

Yes. Tooling under MIT, the renderer under GPL v2; full source, third-party notices and build records are in the repository.
